# Known refusal codes and causes

Experimental, commissioned as a test of the IMD swarm. It may not work as described. Read the code, start with small amounts, no warranty.

This catalog separates input mistakes, language/planning decisions, payment validation, live state and transient availability. It is exported as `knownRefusals`; inspect it with `node bin/imd-validate.cjs --refusals` or add a code to show one entry. The action-input validator does not validate or send an x402 payment.

These are known causes, not an exhaustive server specification or a promise that a code has only one cause. Local diagnostics identify schema failures and a few deterministic preflight hazards. Natural-language evaluation, wallet ownership, existing orders, quotas, schedule existence and provider availability require the server.

| Code | Scope | Known cause | What to change or check |
| --- | --- | --- | --- |
| `invalid_input` | input | An action body breaks a documented type, required field, length, count, enum, format, dependency or exclusion. The server also uses this code for quote-time input rejection. | Read the returned path and problems, correct the input, and validate again. Passing local checks does not guarantee server admission. |
| `invalid_payment_shape` | payment | The strict x402 payment object contains an unexpected key, a wrong field shape or a nonempty SDK extensions object. This is the payment envelope, not the action input. | Use only the payment fields in the Paid requests table. Empty extensions is documented as allowed. Match accepted to the challenge and use the order resource URL and quote deadline. |
| `missing_fact` | semantic | The workflow request does not state the token total supply (missing fact: token_supply); "fixed supply" alone does not give a quantity. | State the numeric total supply explicitly in request, such as "a fixed total supply of 1,000,000,000 tokens with 18 decimals". Keep context and draft consistent. |
| `unplannable_steps` | semantic | Explicit step keys or dependencies require `shape: dag`. In this assignment, gas-and-size-report, write-readme-and-docs and deploy-script steps must not name paths. | Use `shape: dag` for explicit keys and dependencies, and remove paths from those three skills. |
| `protected_path` | input | A write budget names protected `.git`, `.github`, `foundry.toml` or `lib`, including descendants; broad or traversing paths can also reach protected content. | Choose narrow repository-relative writable paths outside `.git`, `.github`, `foundry.toml` and `lib`. Do not ask a step to rewrite protected project infrastructure. |
| `bad_path_count` | input | A task exceeds 16 allowed paths after an extensionless directory path expands to the path and `path/**`. Files and explicit `/**` globs count once. | Reduce or narrow the path list to at most 16 paths after expansion. |
| `recheck_failed` | semantic | The evaluator cannot reproduce or accept the proposed plan, including vague rules or asking adversarial-review to write a failing test. | Replace vague rules with specific observable acceptance criteria. Put test creation in a writing/test skill; reserve adversarial-review for independent read-only review, then recheck. |
| `needs_revision` | semantic | The evaluator needs a clearer or corrected request, including vague rules or asking a read-only adversarial-review step to produce a failing test. | Specify measurable behavior and separate test-writing from review. Revise the request using the reported reasons, then recheck before payment. |
| `invalid_plan` | semantic | The proposed plan is invalid; one known cause is request plus context plus draft objective exceeding about 7,000 characters after folding. Other planning failures can use the same code. | Shorten the combined narrative, state concise facts once, and follow the server blocker details. The approximate folded threshold is separate from each schema string maximum. |
| `objective_too_large` | semantic | The combined workflow request, context and draft objective exceeds the evaluator allowance, observed at about 7,000 characters after folding. | Reduce the combined narrative below the approximate threshold and rerun the server check. JSON Schema field maxima alone do not model this evaluator rule. |
| `payer_not_owner` | payment | A job.continue payment is signed by a wallet other than the wallet that paid for the original project. | Use the parent project paidBy wallet. A valid parentJobId and a valid quote do not establish payer ownership. |
| `request_key_conflict` | state | A requestKey already identifies a quote with a different action or input. | Reuse the same key only for an identical retry; use a new UUID when the action or input changes. |
| `launch_token` | semantic | A project or hook launch asks for a different token than the fixed launch token terms. Project/hook launches use 1,000,000,000 tokens, 18 decimals and plain transfers. | Use those terms for evm_project or univ4_hook, or request custom_token with explicit economics for your own token terms. Supply the token name and symbol. |
| `too_many_publishes` | state | The server publication quota has been reached. This depends on service state and publication history. | Honor Retry-After when supplied and retry later; local body validation cannot determine remaining publication quota. |
| `no_panel` | state | The requested job has no research panel at GET /jobs/:id/panel. This read-route error does not mean the paid input schema is wrong. | Check the job id and whether it is a research-panel job; use the appropriate result route for other job kinds. |
| `unknown_schedule` | state | The schedule id does not identify an available schedule. A syntactically valid UUID does not prove a schedule exists. | Check the id with the schedule read route and use the actual schedule id before topping up. |
| `invalid_owner` | input | The owner filter on GET /schedules is not a valid 0x-prefixed wallet address. This is a read query parameter, not a paid schedule input field. | Use a 0x-prefixed 40-hex-character wallet address in the owner query; do not add owner to schedule.create or schedule.topup input. |
| `evaluation_unavailable` | transient | An evaluator or required evaluation provider is temporarily unavailable; this is a transient service failure. | Retry the unchanged request with backoff and honor Retry-After when present. Inspect the existing order before retrying a payment; do not invent a new payment because evaluation was unavailable. |

## Provenance and conflict handling

Read on **2026-10-02**. The [Paid requests](https://imd.fun/docs#paid), [Job body](https://imd.fun/docs#job-body), [continuation](https://imd.fun/docs#continue), [research reads](https://imd.fun/docs#research), and [schedule reads/body](https://imd.fun/docs#schedules) sections support the documented input, payment, ownership and read-route cases. The assignment additionally requires the observed evaluator causes `missing_fact token_supply`, the three step/path exclusions, protected `foundry.toml` and `lib`, vague-rule/review refusals, the approximate folded 7,000-character limit, and transient `evaluation_unavailable`. They are recorded as assignment requirements rather than invented documentation quotes.

The Job body table lists `gas-and-size-report`, `write-readme-and-docs` and `deploy-script` among skills requiring paths; the assignment explicitly says those three must **not** name paths. The shipped schemas and preflight checks follow the assignment, and the upstream DAG example already omits paths on its documentation step.

The upstream workflow examples say “fixed supply” without a quantity. The shipped examples state a total supply of 1,000,000,000 tokens explicitly, so they do not repeat that missing fact. The approximately 7,000 folded-character planning limit remains distinct from the 16,000-character request/context limits and the 8,000-character draft objective limit.

On **2026-10-02**, live `POST /requests/check` responses showed that explicit `.git` step paths are refused with `protected_path`, `key` or `dependsOn` on a `shape: chain` step is refused with `unplannable_steps`, and nine extensionless directories (or eight directories plus one file) are refused with `bad_path_count` while eight directories and sixteen files pass. The public Job body documentation does not state these three rules. The exact request and response bodies are preserved in [`test/live/check-2026-10-02.json`](../test/live/check-2026-10-02.json).

The follow-up live checks on **2026-10-02** also refuse `.github` and its descendants, accept `.vscode` and exactly `./.git/config`, and report `launch_token` as a blocker. The library preserves that exact path exception and reports its existing launch-token heuristic as an error. These observations are saved in [`test/live/check-followup-2026-10-02.json`](../test/live/check-followup-2026-10-02.json).
